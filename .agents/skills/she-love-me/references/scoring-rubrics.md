# 评分量表（六维好感度 / 回复评分）

本文件定义「她不一样」的两套评分量表：

- **六维好感度**（`analysis.json` 的 `affinity`）— 量**对方对你有没有好感**，接进模块 A5
- **回复评分**（`analysis.json` 的 `reply_grades`）— 量**你自己的回复好不好**，接进模块 D6

> **来源与许可**：六维维度定义、5 档量表、权重、边界封顶规则移植自
> [Reverie0123/crush-monitor-universal](https://github.com/Reverie0123/crush-monitor-universal)
> （MIT License，Copyright © 2026 Crush Monitor contributors），取自 `shared/affinity.ts`；
> SSS–D 档次与阈值取自同项目 `shared/ratings.ts`。
> **本文档按本项目框架改写的是「出分规则」**——原实现直接加权求平均，本文档改为
> 证据分级 + 锚点标注（原因见下）。

## 第一部分：六维好感度

### 1.1 与 `symmetry_score` 的分工 ⚠️ 先读这条

这两个分数**测的是两件事，正交，不得互相替代**：

| | `symmetry_score`（0–10） | `affinity.total`（0–100） |
|---|---|---|
| 测什么 | 双方投入**对不对等** | **对方对你有没有好感** |
| 对谁敏感 | 双方都算（你自己太主动也会拉低） | 只描述对方一侧 |
| 典型反例 | 一方发起很少、但每次接得住 → symmetry 低 | 同一场景下 affinity 可能并不低 |

**报告里必须分开呈现，不得用一个去解释另一个。**
把「她很少主动」直接读成「她不喜欢你」，是这两轴被压成一个之后才会犯的错。

### 1.2 六个维度与权重

| key | 标签 | 权重 | 核心问题 |
|-----|------|------|---------|
| `initiative` | 主动延续 | 15 | 对方是否主动开启或延续交流？**不要靠消息条数推断** |
| `engagement` | 回应投入 | 20 | 对方对你说的**具体内容**投入了多少注意？**短句、回复慢、忙碌本身不扣分** |
| `care` | 关心体贴 | 20 | 是否针对你的感受/需要/处境表达**个人化**关心？礼貌客套与具体关心分开判断 |
| `openness` | 自我开放 | 15 | 是否愿意让你了解自己的生活、感受和想法？**正常隐私边界不是疏远** |
| `intimacy` | 亲密表达 | 20 | 是否表达**被双方接纳**的特别亲近或恋爱意味？朋友间热闹、通用表情、普通夸奖不自动等于暧昧。**情侣也需看当前实际表达，不按关系设置加分** |
| `action` | 实际行动 | 10 | 是否把接近落实为时间安排或具体行动？**没有邀约机会不等于拒绝；因忙改期且给出替代安排是积极信号** |

> 六段问句里的加粗部分**逐字保留了上游原文**，因为每一条都恰好是本项目历史上踩过的坑。

### 1.3 五档量表

每维五档，**档 1 最低、档 5 最高**：

**`initiative` 主动延续**
1. 明确不愿继续交流
2. 有交流机会但只被动应付或反复终止话题
3. 自然接话，愿意保持交流
4. 主动追问、展开话题或在结束后重新找话题
5. 持续主动创造交流机会，并具体表达想与你保持联系

**`engagement` 回应投入**
1. 明确无视或贬低你的表达
2. 多次有回应机会却回避重点、只作敷衍应答
3. 正常回应问题，基本接得住话题
4. 回应细节、接住玩笑或认真展开你的话题
5. 持续专注地理解和回应你，主动跟进此前提到的具体事情

**`care` 关心体贴**
1. 明确嘲弄或漠视已表达的困难和感受
2. 在你表达需要时明显不愿回应或只敷衍
3. 普通礼貌与基本照顾，未见针对个人的特别关心
4. 具体理解、安慰你，记得其偏好或困扰
5. 主动持续照顾你的感受和需要，并提供具体支持

**`openness` 自我开放**
1. 明确拒绝让你了解自己并要求保持距离
2. 有相关话题但刻意保持非常表面的交流
3. 自然分享一般日常与观点
4. 主动分享个人细节、真实感受或寻求你的看法
5. 展现明显信任，主动分享脆弱感受、重要经历或内心想法

**`intimacy` 亲密表达**
1. 明确拒绝恋爱或亲密接近，且当前仍有效
2. 明确限定普通关系、排除暧昧意味
3. 友好自然但没有明确恋爱意味，或亲近暗示尚不确定
4. 有针对你的特别称赞、想念、亲昵称呼或被接住的暧昧
5. 明确表达恋爱喜欢、爱意或双方接纳的亲密愿望

**`action` 实际行动**
1. 明确拒绝进一步接触，且没有替代意愿
2. 有推进机会却反复含糊回避或拒绝且无替代安排
3. 只谈一般可能性，或这段聊天尚未涉及具体行动
4. 主动提出、接受具体相处安排，或没空但积极给出替代安排
5. 双方具体安排得到确认，或有直接文字证据表明已兑现关心与相处行动

### 1.4 量化锚点可得性 ⚠️ 动手前必读

**这是本量表最容易被误用的地方。** 六个维度里**只有一维**有干净的统计锚点。

| 维度 | 权重 | 量化锚点 | 现在拿得到吗 |
|------|------|---------|-------------|
| 主动延续 | 15 | `c_metrics.session_gaps.{h3,h6,h12}.them_starts` | **✓** 三套口径并存，**引用时必须写明用哪套**（见 `risk-signals.md` 的口径表） |
| 回应投入 | 20 | `reply_speed.their_avg_seconds`（**均值**；中位数口径已作废）<br>`turn_response.them_to_me.median_chars` | **△ 均为代理**——`turn_response` 是**回复长度**不是投入度，代码注释明确写它是「a proxy, not engagement」 |
| 关心体贴 | 20 | `affect.semantics.care_intensity` | **△** 仅当 `affect.status == "ok"` 时可用，且属辅助层 |
| 自我开放 | 15 | — | **✗ 无字段** |
| 亲密表达 | 20 | — | **✗ 无字段**——亲昵称呼被折进 `positive_emotion_count`，拆不出来 |
| 实际行动 | 10 | — | **✗ 不存在**——`c_metrics.future_statements.available = false` |

**铁律：`basis == "quant"` 的维度，必须在 `derivation` 里写明用的是哪个字段、哪套口径。**
**锚点不存在时，`basis` 只能写 `"text"`，不许编一个数假装是统计出来的。**

### 1.5 出分规则

每一维输出：

```json
{
  "key": "主动延续",
  "weight": 15,
  "level": 3,
  "score": 50,
  "basis": "quant",
  "derivation": "c_metrics.session_gaps.h12.them_starts = 4（口径 12h），对照基线判为档 3",
  "evidence_level": "medium",
  "note": "……",
  "evidence": [{"quote": "……", "date": "2026-09-27"}]
}
```

**档位 → 分数**（唯一允许的映射）：

```
level 1 → 0    level 2 → 25    level 3 → 50    level 4 → 75    level 5 → 100
```

**硬规矩：`basis == "text"` 的维度，`score` 只能取 0 / 25 / 50 / 75 / 100 这五个锚点值。**

**为什么**：五档量表就是它的分辨率。没有统计底的情况下给出 `72` 这种数字，是**假精确**——
它让一个纯文本判断看起来像测出来的。只有 `basis` 为 `quant` 或 `mixed` 的维度，
才允许在档内取精值（且 `derivation` 必须写明精调依据）。

**`evidence_level` 复用 `report-schema.md` 的既有四级**（`high` / `medium` / `low` / `insufficient`），
**不新增第五个取值**。判定标准同该文件的表（数量 / 独立性 / 一致性三条同时看）。

**证据不足时输出 `status` 语义**（对应上游 `Judgment.status`）：
用 `evidence_level: "insufficient"` 表达，**不要给 0 分**——0 分是「明确不愿继续交流」，
和「没数据」是两件完全不同的事。

### 1.6 总分与封顶

**总分只在 ≥4 个维度有 `score` 时才输出**：

```
total = round( Σ(weight × score) / Σ(weight，仅计有 score 的维度) )
```

- 不足 4 维有分 → `total: null`，并在 `total_reason` 写明缺哪几维、为什么
- `basis` 为 `text` 的维度参与加权时，**在 `total_note` 里点名**，让读者知道这个数有多少是靠文本推断的
- 加权公式与上游 `composeAffinity()` 一致，**但上游要求六维全非 null 才出分；本项目放宽到 4 维，
  前提是缺的那几维必须显式写明**——放宽的是可得性，不是宽松度

**边界封顶 `boundary_applied`**：

- **触发源**：`moments` 里检出有效的 `boundary` 时刻（拒绝 / 划清界限），且**该边界未被后续 `reopen` 撤回**
- **效果**：`boundary_applied = true` → `total = min(25, total)`（沿用上游 25 的封顶值）
- **必须写明 `boundary_reason`**，并附原文锚点。没有锚点不得触发
- `reopen` 时刻会把对应 `boundary` 的状态置为 `resolved`（沿用上游 `MemoryEvent.status` 语义），
  **被撤回的边界不再封顶**

> 参照上游实现：`boundaryApplied = boundary >= 0.8`；本项目把「边界概率」换成
> 「检出未撤回的 `boundary` 时刻」——这是个**更硬**的触发条件，因为它是基于实际文本事件的，
> 不是模型自报的一个概率值。

## 第二部分：回复评分（SSS–D）

### 2.1 适用边界

**只评用户自己发出的消息**，不评对方。这是给用户看的自我校准工具，接进模块 D6。

不要对每条消息都评——**只评关系意义上的关键回复**：对方发起邀约时你怎么回的、
对方示弱时你怎么接的、你情绪上头时发了什么。

### 2.2 七档量表

| 等级 | 分数区间 | 含义 |
|------|---------|------|
| **SSS** | 95–100 | 非常出彩，表达自然且精准接住语境 |
| **SS** | 90–94 | 优秀，兼顾情绪、分寸和话题延续 |
| **S** | 80–89 | 很好，有效回应且让交流更顺畅 |
| **A** | 70–79 | 合适，回应自然且照顾语境 |
| **B** | 60–69 | 基本合适，但表达还有提升空间 |
| **C** | 40–59 | 较弱，可能接话生硬或忽略对方情绪 |
| **D** | 0–39 | 不合适，可能造成压力、冒犯或难以继续交流 |

### 2.3 输出结构

每条评分**必须**带：

```json
{
  "quote": "用户的原话",
  "date": "YYYY-MM-DD",
  "context": "对方刚说了什么 / 当时什么状态",
  "grade": "D",
  "score": 35,
  "reason": "为什么要打这个分（结合语境，不是泛泛而谈）",
  "alternatives": [
    "换一种说法的版本一",
    "换一种说法版本二",
    "保持沉默 / 不补第二句"
  ]
}
```

**两条到三条替代表达**，其中**「不回复」是合法的替代表达**——
本项目语料里最反复出现的问题恰恰是「该停的时候补了第二句」，
所以「沉默」必须作为一个真实选项出现，不能只给「换句话怎么说」。

**评分必须引用语境**：同一个「哦」在热络语境和冷淡语境里分数差极大。
没有 `context` 字段的评分，视为无效。

## 第三部分：两套量表的关系

| | 六维好感度 | 回复评分 |
|---|---|---|
| 评谁 | 对方 | 你自己 |
| 流向 | A5 → `affinity` | D6 → `reply_grades` |
| 用在哪 | 判断关系状态与推进空间 | 校准你下一步怎么说话 |
| 共同纪律 | 档位锚点优先于精值；证据不足不给分；必须附原文 | 同左 |

**两套量表都服从同一条顶层纪律**：`analysis-framework.md` 的「无证据不诊断」。
词表和档次只是**归类工具**，不是结论本身。
